# Rallyloom v0.21.6

源码公开的 OA 底座与团队虚拟办公室桌面应用。前端使用 React 19、TypeScript、Vite、Tailwind 和 **shadcn/ui 官方组件**，并通过 Electron 打包为 Windows 桌面程序。
定位：**被接入方**——提供入口、接入规范与中性身份容器，任何系统按规范写适配器接入；客户端零存储，数据落超管配置的云端。

**必接板块（底座自带，定位即承诺）**：团队管理 · 办公室 · 交流室 · 任务看板 · 通知中心 · 文档中心。其余板块均为后期二开插槽（见 [docs/oa-foundation-plan.md](docs/oa-foundation-plan.md)）。

## 功能（v0.21.6）

### 文档阅读器：全宽阅读、大纲收缩、缩放下限与图片双击放大（v0.21.6 新增）
- 阅读器工具条新增：缩小 / 百分比 / 放大（80%–160%，步进 10%）、全宽阅读（隐藏大纲、纸面扩展到 1180px）、大纲折叠按钮；正文默认字号提高到 15.5px、行高 1.88，标题层级同步放大。
- 文档正文（编辑器与阅读器）里的图片支持 **双击在应用内放大**：从原图位置 FLIP 过渡展开到视口居中，点击空白处或按 Esc 缩回原位置并淡出背景遮罩。
- 放大层为独立 portal（`[data-doc-viewer]`），带深色玻璃背景、右上关闭按钮与「点击空白处返回文档」提示，不打断文档滚动与选区。

### 文档大标题与现代化段落菜单（v0.21.5 新增）

- 编辑页顶部恢复「大标题」：它就是文档的名字，新建时默认显示「无标题文档」，可以直接点击改名，也可以继续在文档中心右键重命名。
- 段落样式下拉改成现代化浮层菜单：正文 / 一级标题 / 二级标题 / 三级标题带图标、快捷键标签与选中勾选，不再是系统原生的下拉框。
- 去掉编辑页里两条多余说明（「文档名和所在文件夹在目录或卡片上右键修改」「保存内容按 doc.upsert 契约承接」）。

### 新建文件夹弹窗精简（v0.21.4 修复）

- 去掉「知识库」这一层概念：新建文件夹只填一个「文件夹名称」，位置由你当前所在的目录决定（在根目录新建就是一级文件夹，在某个文件夹里新建就是子文件夹）。
- 弹窗里直接写明将创建在哪里；顶部会自动定位到刚建好的文件夹，不会再出现「知识库」「文件夹」两个名字让人看不懂的情况。

### 文档中心：先文件夹、后文档 + 右键管理（v0.21.3 新增）

- **先文件夹，再文档**：新建文档必须在文件夹内进行；没有选中文件夹时点「新建文档」会提示并引导先创建文件夹，空态也改成「先创建一个文件夹」，避免根目录里堆一堆散文档。
- **编辑页只写正文**：新建 / 编辑页面里不再出现「文档名称」「知识库」「文件夹地址」这些输入框；文档名默认「无标题文档」，保存后用右键改名。
- **右键管理**：左侧目录与文档卡片支持右键——文档可「打开 / 重命名 / 删除」，文件夹可「新建文档 / 新建子文件夹 / 重命名 / 删除」；重命名通过 `client.update` 同步到企业工作区，路径型目录会批量更新其下文档的 folderPath。
- 目录顶部仍可新建文件夹；文件夹重命名 / 删除只对真实登记的文件夹提供，从文档路径推断出来的目录改名会同步所有下属文档。

### 墙体高度统一（v0.21.2 修复）

- 自由墙、房间隔墙与外墙此前各用一套高度（自由墙沿用数据里的 26/60，外墙北侧 34、其余 16），所以看起来忽高忽低。
- 现在渲染层统一使用 `WALL_HEIGHT = 44`，编辑器新建墙体写 44，六个分区的玻璃隔断与实墙、外围墙同高。

### 房间标题统一对齐（v0.21.1 修复）

- 房间名不再逐格寻找“空位”，统一贴在每个分区的左上角（固定 inset 18×16），同一排房间标题在同一基线上，门洞只做固定步长的纵向让位。
- 覆盖老板办公室 / 技术组 / 管理办公室 / 管理组 / 公共客厅 / 运营组六个分区，标题位置固定后点击选房与视觉扫描都更稳定。

### 按角色分区、自由走动与游戏式对话（v0.21.0 新增）

- **按角色分区**：老板办公室（平台总管理员）、技术组（平台管理员）、管理办公室（租户超管）、管理组（租户管理员）、运营组（普通员工）、公共客厅（无固定工位，供走动交流）；测试/演示账号与莫斯科等不需要的成员不分配工位（无座位即不进入房间交流室）。
- **办公室重新装饰**：六个分区重新铺排为「老板办公室 / 技术组 / 管理办公室 / 管理组 / 公共客厅 / 运营组」，每个分区带完整家具组（工位、会议桌、沙发、绿植、灯具、地毯、看板），保留中央公共客厅作为走动与交流空间。
- **只能坐自己的工位**：座位分配即房间交流室成员；点击别人的空工位会被拦下并提示「只能坐在自己的工位上」，座位上有人时通过右键菜单发起私聊或进入房间群聊。
- **游戏式对话**：原「气泡窗」改为从画面底部升起的对话面板（头像徽章 + 房间/私聊标识 + 最近对话 + 快捷回复 + 转为任务），Enter 发送、Esc 关闭，对话同步到交流室。

### 座位等于交流室成员与删除归档保护（v0.20.0 新增）

- **座位即会话**：分配工位即加入该房间的 `room:<roomId>` 交流室，移出工位即退出；交流室频道列表直接显示每个房间的成员与在线数。
- **删除保护**：编辑办公室时，删除已聊过天的房间会先弹出「房间已经聊过天，确认删除？」，给出消息条数并说明房间与交流室会归档、历史保留在企业数据库；从未聊过天的房间直接删除。拆改墙体导致房间消失时也会走同一保护。
- **接入约定**：供应商需保证 `GET /oa/chat/channels` 返回所有房间频道（含空房间），且已有聊天记录的房间删除时只归档、不物理删消息（`agent-skill/provider-api.md` §12.3）。

### 办公室全员入座（v0.19.1 修复）

- **座位不再按「在线态」渲染**：企业接入（如 Mira）通常只给当前登录账号 `online`，其余成员是 `offline`；旧逻辑会把离线成员从 3D 场景里整个跳过，于是「分配了工位却没人坐」。现在座位占用与在线态解耦——被分配到工位的成员始终显示在自己的座位上，房间标签的「N 在岗」仍只统计真正在线的成员。
- **全部 44 名成员集中到运营部**：真实 Mira 工作区重排为六个区域无缝铺满 1250×771（茶水休息间 / 老板办公室 / 会议室 / 公共办公区 / 技术部 / 运营部），运营部 136.1 ㎡ 内放置 11 列 × 4 排 = 44 个旋转工位，44 人全部 `assignments` 到运营部并固定 `seatAssignments` 0–43，打开办公室即可看到每人坐在自己工位上；后续在编排器里继续调座位也不会再「消失」。
- 验证：真实工作区 `data-seats=59 · data-seated=44 · people=44`，运营部 1 在岗（在线语义不变）；演示数据同样全员显示。

### 办公室编辑器快捷键（v0.19.0 新增）

- **删除**：选中家具、墙体或房间后按 `Delete` / `Backspace`，不必再去右下角找删除按钮。
- **编辑操作**：`Ctrl+Z` 撤回、`Ctrl+Shift+Z` / `Ctrl+Y` 重做、`Ctrl+C/X/V` 复制/剪切/粘贴、`Ctrl+D` 复制一份、`Ctrl+S` 发布。
- **视图与变换**：方向键微调（`Shift` 加速）、`R` / `Shift+R` 旋转 ±90°、`V/W/O` 切换选择/自由墙/开门工具、`Esc` 取消当前选择或工具、`0` 复位缩放、`+/-` 缩放画布。
- 连续微调会合并成一步撤销；所有快捷键在输入框内自动让行，不会误触。
- 同时修正了演示工作区种子布局中若干家具越过房间边界的问题（此前会导致编辑器认为布局无效、发布按钮不可用）。

### 公告只来自通知中心（v0.18.4 修复）

- 办公室顶部的公告浮窗不再内置任何「系统公告」，唯一数据来源是通知中心（企业工作区下发的通知记录）；通知中心为空时浮窗不会出现。
- 已阅后写入本机 `localStorage`，不会重复弹出；点击「查看全部」进入通知中心。
- 企业工作区需要下发通知（`/oa/notices`）才会有公告，客户端不虚构公告内容。

### 交流室与文档中心的可用性修复（v0.18.3）

- **交流室频道列表直接显示人数**：进入交流室后会预取所有频道的成员信息，频道行直接显示「N 人 · M 在线」；同步中显示「正在同步成员…」，失败显示「成员暂不可用」，不再需要先点开频道才知道有多少人、多少人在线。
- **空聊天记录说明**：群聊为空时补充「聊天记录来自企业工作区，发送第一条消息即可开始」，明确这是空频道而不是加载失败（聊天记录由提供方持久化，实测发送后刷新仍在）。
- **文档中心空态重做**：空列表从一行灰字改成「图标 + 标题 + 说明 + 操作」的品牌卡片，明确写出「文档由企业工作区统一管理；当前工作区返回 0 篇」，避免被误认为没有刷新出来；错误态与加载态使用同一套卡片，并保留「新建文档」入口。

### 办公室公告与播放器（v0.18.1 调整）
- **公告完整展示 + 已阅自动收起**：公告浮窗从「一条矮横幅」改为完整卡片——标题、正文、来源（`sourceId · externalNoticeId`）、级别与置顶、属性标签全部展示（宽度 `clamp(380px, 40vw, 556px)`，实测 556×223），不再截断；底部「已阅」为主按钮，点击后 180ms 收起动画并自动展示下一条未阅公告，读完后浮窗自然消失；已阅记录存本机 `localStorage`（按公告 id，最多保留 200 条），重开应用不再打扰
- **播放器就是播放器**：删掉底栏「点歌台」跳转按钮与所有跳转逻辑（含封面点击跳转、YouTube 曲目「去点歌台播放」提示）——缩窄后的底栏更干净：黑胶封面 / 曲目 / 进度 / 上一首·播放·下一首 / 音量
- **YouTube 曲目在底栏直接播放**：桌面端（`file://` 页面）里 YouTube embed 播放器会被判为配置错误（错误 153），因此改为隐藏 `<webview>` 加载 watch 页并直接驱动页面 `<video>`（独立 `persist:rallyloom-media` 分区 + 标准 Chrome UA + 视频元素起播兜底），底栏即可播放企业下发的 YouTube 歌单；实测 Mira 工作区曲目 `BbY WOW` 从 0:03 播到 0:32（时长 3:48）

### 办公室背景音乐与品牌画布（v0.17 新增）
- **办公室底部 BGM 播放条**：办公室页底部悬浮一条玻璃质感播放器（黑胶封面 / 曲目与歌手 / 可拖动进度 / 上一首·播放暂停·下一首 / 音量 / 播放均衡器），正好落在 3D 场景下方原「空白带」上，不遮挡画布操作。
- **与点歌台同一份曲库、同一个播放器**：底栏跟着点歌台走——点歌台切歌它同步（黑胶旋转、进度、音量），从点歌台回到办公室可以接着听；底栏不再提供跳转按钮，就是一个播放器。曲库仍只来自工作区（bootstrap 的 `jukebox` 歌单或共享曲库接口），Rallyloom 不存媒体。
- **YouTube 曲目**：v0.18.1 起底栏可直接播放（隐藏 `<webview>` 驱动 watch 页的 `<video>`），不再跳去点歌台。
- **品牌画布**：除办公室外的页面统一换成 Rallyloom 自有底纹——冷调浅灰白（v0.18.2 起 `--rl-canvas #f4f6f7`；v0.17 的暖白 + 沙金晕染已废弃）+ 极淡钢蓝 / 青绿两层晕染 + 26px 细网格；页头分隔阴影、文档空态引导卡、交流室空态图标同步统一，替代原来的灰底（`#f3f3f2` / `#f4f4f6`）。

### 交流室过渡与玻璃表面（v0.17.1 修复）
- **整面加载遮罩**：切换会话或首次载入消息时，加载态不再只盖住消息列表（旧版输入框露出白底、上下割裂），而是覆盖整个会话区——页头、消息列表、输入框一起被品牌化遮罩盖住，载入完成后 260ms 淡出；遮罩带「正在载入消息…」与当前会话名，`prefers-reduced-motion` 下关闭动画
- **玻璃会话表面**：聊天表面从「白色板 + 一圈灰底」改为半透明玻璃（`rgba(255,255,255,.76)` + `backdrop-filter: blur(18px) saturate(1.28)`，14px 圆角），消息列表底、页头、输入框、成员面板同步半透明，页面品牌底纹从顶部到底部连续透出，不再有白板接缝

### 集团与租户联邦（v0.10 新增 · 可选管辖层 + 集团超管演示档）

- **集团 = 可选能力**：不是所有公司都是管辖体系——`tenant` 增加可选 `groupId/groupName` 字段，不属任何集团的公司（多数部署）不带字段、链路零感知；多租户基线不变
- **合并租户 = 归属同一管辖体系的配置**：分公司法律上是独立租户（股份问题），数据仍按公司硬隔离；集团层提供联邦目录（公司归属 = `attrs["公司"]` 中性属性，无新 Schema）与「策略跟随总部」标记
- **集团超管演示档**：登录页新增「星澜控股集团 · 集团超管（姜衡）」——平台运维轴化身，**不进任何公司成员表**：左上角显示集团名，直接进入集团控制台（两家公司卡片：成员/在线统计、总部·策略制定方 vs 策略跟随集团总部；42 人合并成员目录按公司 chip 着色），「进入工作区」以对应公司超管身份下钻
- 集团视图只读（`DemoGroupClient`），管理动作进工作区后执行；规范见 agent-skill `integration-spec.md` §10.1（agent-skill v1.5）——对接入方纯文档版本，字段/事件/端点零新增

### 点歌台（v0.16 · 工作区共享曲库）

点歌台是 OA 内置的共同曲库。成员可直接拖入 MP4、播放同事分享的歌曲；Mira 按当前公司范围每天统一随机选一首。成员曲库由 Mira 的授权 OA API 存储和提供，可选的 `bootstrap.jukebox.playlists` 仅作为精选歌曲来源，用户不必准备媒体直链或配置点歌说明。

- 曲库列表展示歌名、上传者和上传时间；支持搜索、播放队列、音量、全屏以及拖放或选择 MP4 上传。
- 成员 MP4 上传上限为 20 MiB；文件和每日歌曲结果按工作区范围隔离。
- 同一工作区当天看到相同随机歌曲；每日结果由服务端持久化，删除当日选中歌曲后重新抽取。
- 正式接口、权限、租户边界和 feed Schema 见 `agent-skill/integration-spec.md` §13、`agent-skill/schemas/jukebox-feed.schema.json`；可选精选歌单仍见 `agent-skill/schemas/jukebox.schema.json`。

## 自检截图（开发用）

## 深链协议（企业授权回调）

- 主进程 `app.setAsDefaultProtocolClient('rallyloom')` 注册协议：冷启动走 `process.argv`，热启动走 `second-instance`，两路都交给 `forwardDeepLink()`，校验通过后把窗口抬到前台
- **回调地址等价格式**：Chromium 会把自定义协议的空路径补成 `/`（`rallyloom://callback/?code=…&state=…`），Windows 再原样交给应用；`electron/workspace-auth.cjs` 的 `callbackState()` 同时接受 `rallyloom://callback` 与 `rallyloom://callback/`，`state` 必须与本次登录一致且只出现一次
- **失败可诊断**：每次回调都会写 `%APPDATA%\Rallyloom\rallyloom-deeplink.log`（`RALLYLOOM_DEEPLINK_LOG=0` 可关闭），记录协议注册结果、argv、是否受理及拒绝原因；授权码 3 分钟内有效
- **兜底通道**：浏览器未拉起应用时，登录页「等待企业授权」下方可粘贴 `rallyloom://callback?…` 手动完成（`workspace:callback` IPC）
- 真接入 OIDC：IdP 侧注册回调 `rallyloom://callback`；code 换 token、bootstrap 全部在主进程完成（Node fetch），渲染层不接触令牌

## 更换 Logo

1. 更新 `src/assets/rallyloom-mark.svg`。标题栏、登录页和网页标签页共用此文件。
